# 軟體設計文件（SDD）第二版：台灣九合一選情分析小工具

版本：2.0  
更新日期：2026-10-10

## 目的與範圍

本文件定義 2026 年台灣地方選舉縣市長選情儀表板的第一版架構、資料表示方式、比較規則、互動規則與部署方式，作為後續實作的依據。第一版聚焦台北市長選情，以公開民調和歷史選舉結果呈現可查證的觀測資料，並在輸入資料與公式條件齊備時提供有明確假設的情境試算。

第一版不提供勝選機率或未經驗證的綜合預測，不串接即時爬蟲、不建立使用者帳號，也不需要後端 API 或資料庫。網路聲量僅在找到可追溯且可重複更新的資料來源後，才以獨立背景資料加入；不納入試算公式。

## 系統架構

```text
GitHub repository
  └─ Workers Builds
       └─ Vite build
            └─ dist/ 靜態資產
                 ├─ React 儀表板
                 └─ data/*.json

瀏覽器
  ├─ 讀取靜態 JSON
  ├─ 顯示民調、歷史結果與來源
  └─ 執行情境試算並更新圖表
```

應用程式不需常駐 Python 伺服器。民調和基準資料以版本控制中的 JSON 維護；前端讀取資料後在瀏覽器端計算，滑桿變動不需呼叫遠端服務。第一版不導入 D1、KV、R2 或其他資料庫，避免為靜態、小型資料集增加維運元件。

建議目錄：

```text
src/
  app/             # 頁面與應用程式狀態
  components/      # 圖表、資料來源、情境控制元件
  data/            # 型別、驗證與轉換函式
  simulator/       # 純函式情境試算
public/data/
  polls.json
  baseline.json
  sentiment.json   # 可選；有合格來源後才加入
wrangler.jsonc
```

## 資料模型與來源

每筆民調至少記錄：`poll_id`、`city`、`election`、`pollster`、`sponsor`、`fieldwork_start`、`fieldwork_end`、`published_at`、`sample_size`、`population`、`method`、`margin_of_error`、`question_text`、候選人支持度、未決定比例、來源 URL 與資料建立時間。欄位未知時使用明確的空值，不自行補值。

民調資料保留各機構原始數值和候選人情境。同一趨勢系列須同時符合相同縣市與選舉、相同候選人組合、相同調查母體，以及題目所描述的候選人支持情境實質相同。不同民調機構的結果可以各自標示在同一時間軸，但每個點都需保留機構和來源；只有符合上述條件的點才可連線。調查方法仍須顯示，不要求不同機構使用相同方法才可放在同一系列。

若候選人名單、調查母體或題目情境不一致，資料必須分成不同系列或只以未連線資料點呈現。不得將不同情境的結果以折線連接，也不得以插值或平滑製造沒有調查的日期。30 天視窗只顯示該期間實際存在的資料；資料不足時顯示資料不足狀態。

歷史選舉結果另存候選人、政黨、票數、得票率、投票率、選舉日期及來源，作為背景比較，不併入民調支持度。任何測試假資料必須帶有 `is_mock: true`，介面亦須清楚標示模擬資料。

民調來源優先使用公開且附調查方法、樣本數及調查日期的原始報告；每筆資料連回原始報告。舉例而言，TVBS 民調中心提供民調報告與部分年齡交叉資料，但資料輸入仍須逐份核對。[TVBS 民調中心](https://www.tvbs.com.tw/poll-center)

公開發布資料前，需逐一核對來源的使用條款、允許重製的資料範圍和要求的標示方式。無法確認可否重製時，不公開擷取的數值；可保留來源連結並標示該資料尚未納入。

## 情境試算

試算的目的是展示明確假設下的支持結構敏感度，不是估計選舉結果。試算資料模型須記錄來源民調、使用的年齡組支持度、選民占比或基準投票率假設、滑桿值、未決定選民處理方式與公式版本。畫面同時呈現假設摘要及「情境試算，非選舉預測」標示。

情境試算有條件納入 MVP，但不保證首次部署時一定啟用。啟用前必須備妥可追溯的 20–29 歲候選人交叉支持度、族群人口權重、基準投票率、未決定比例處理方式，以及明確記錄版本的公式。資料集亦須能支持公式對所有候選人或其餘選民群體的計算；不可用未觀測到的分布補值。

若任一必要輸入或公式規則未備妥，滑桿保持停用並列出缺少項目。不得以全體支持度代替年齡交叉表，也不得推估不存在的青年投票率。功能啟用後，使用者調整的是明確標示的投票率假設，輸出稱為「情境試算」，不稱為實際投票率、預估得票率或勝率。

試算程式採純函式，輸入明確、輸出可重現。調整滑桿時僅重新計算受影響的試算結果與圖表，不重新載入資料。公式、未決定比例處理、基準值及必要資料欄位必須在試算實作開始前寫入規格；在這些規則尚未定義前，只能完成其他儀表板功能及試算停用狀態。

## 主要介面

1. **選情總覽**：呈現最近可用民調的候選人支持度，附調查日期、樣本數、機構和原始報告連結。
2. **民調趨勢**：展示最近 30 天內實際有資料的民調點；資料稀少時明示，不平滑或補出趨勢。
3. **歷史結果**：獨立呈現最近一次可用的台北市長選舉結果與投票率。
4. **情境模擬**：呈現 20–29 歲族群投票率假設及試算變化；資料不完整時呈現停用原因。
5. **資料說明**：列出資料更新日期、來源、欄位定義、假資料標示及試算假設。

介面需支援手機與桌面寬度、鍵盤操作、圖表文字摘要和足夠的色彩對比。候選人不只以顏色區分，圖表需有清楚標籤及來源提示。

## 部署與更新流程

GitHub 為原始碼與資料版本的唯一來源。部署前必須先初始化 Git 儲存庫，建立或連接 GitHub 專案，並確認主要分支。完成後，Workers Builds 監看該分支；提交後執行相依套件安裝與 Vite 建置，並將 `dist/` 部署為 Workers 靜態資產。資料更新透過修改 JSON 並提交變更完成，部署版本可追溯至 Git commit。Cloudflare Drop 僅作臨時預覽，不作正式自動化部署管線。

第一版沒有使用者提交資料、登入或私密設定，因此不保存使用者資料，也不需要密鑰。若未來加入外部 API、資料庫或使用者功能，須另行設計伺服器端邊界、權限及資料保存政策。

## 品質與驗收條件

- 首次開啟預設顯示台北市，選情數字附來源與日期。
- 30 天趨勢只畫出來源資料中實際存在的民調；只有候選人組合、調查母體與題目情境符合比較條件時才連線。
- 不同候選人組合、調查母體或題目情境的結果不會被連成同一趨勢；資料不足時顯示明確狀態。
- 假資料在資料列和介面上都清楚標記。
- 青年投票率情境在全部必要資料、公式及未決定比例規則備齊時啟用，試算結果附帶可閱讀的假設說明；否則停用並列出缺項。
- 任何頁面都不將試算標成勝率、民調結論或已驗證的得票預測。
- 公開的每筆資料皆有來源連結和所需標示；來源使用條款未確認的資料不公開擷取數值。
- 資料讀取和試算可在沒有後端 API 的情況下完成。
- GitHub 儲存庫和主要分支建立後，變更可自動建置並部署至 Cloudflare Workers Static Assets。
- 驗收須覆蓋趨勢分組、資料不足狀態、試算停用與來源標示；不要求建立完整自動化測試套件。

## 尚待實作時確認

- 圖表套件選型，以及圖表的輔助閱讀方式。
- 民調與歷史結果 JSON 的完整欄位 schema 和資料驗證規則。
- 20–29 歲情境的資料來源、人口權重、基準投票率、未決定比例處理規則及公式；未確認並記錄前，情境保持停用。
- 各民調來源的重製條件和必要標示方式；確認前不得公開擷取數值。
- GitHub 與 Cloudflare Workers Builds 的專案連線及正式網域設定。
